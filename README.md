# Direct Materials — выдача материалов через Instagram Direct

Сервис автоматически отправляет ссылку на материал человеку, который оставил комментарий с ключевым словом. Владелец аккаунта настраивает всё в веб-панели: выбирает публикацию, задаёт слова, тексты сообщений и ссылку. Дальше сервис обрабатывает комментарии и показывает историю отправок.

Например, автор предлагает написать «гайд» под постом. Читатель получает сообщение в Direct, нажимает «Получить», а сервис проверяет подписку и отправляет ссылку. Это позволяет выдавать инструкции, подборки и другие материалы без ручного ответа каждому человеку.

## Как это работает

1. Владелец подключает профессиональный Instagram-аккаунт через официальный вход.
2. Создаёт кампанию для конкретной, любой или следующей публикации либо Reel.
3. Задаёт ключевые слова, сообщения, кнопки и ссылку. Перед запуском видит предварительный просмотр.
4. Подходящий комментарий запускает сообщение в Direct с кнопкой «Получить».
5. После нажатия сервис проверяет подписку. Подписчик получает материал; остальным предлагается подписаться и повторить проверку.
6. В панели сохраняется результат: сообщение отправлено, ожидается подписка, материал выдан или возникла ошибка.

Можно включить публичный ответ под комментарием и задать несколько вариантов его текста. Он отправляется после подтверждённой отправки первого сообщения в Direct.

## Что я разработал

- **Панель управления на React:** список кампаний, редактор условий и сообщений, предварительный просмотр, состояние подключения и история выдачи материалов.
- **Подключение Instagram:** официальный вход, обработку разрешений, защищённое хранение токена и получение событий о комментариях и нажатиях кнопок.
- **Правила запуска кампаний:** выбор публикации, поиск ключевых слов и привязку кампании к следующему посту. Например, слово «курс» находится в «Хочу КУРС!», но не в «экскурсия».
- **Полный сценарий выдачи:** первое сообщение, проверку подписки, повторную проверку, отправку ссылки и необязательный ответ под комментарием.
- **Обработку сбоев:** очередь событий, защиту от повторной выдачи по одному комментарию, сохранение состояния каждого шага и инструменты восстановления доставки.
- **Тесты:** проверку правил сопоставления, переходов между этапами, интерфейса и работы серверной части в среде Cloudflare.

Если Instagram не подтвердил отправку, сервис сохраняет неопределённый результат для разбора. Если статус подписки неизвестен, ссылка остаётся невыданной. Эти состояния видны владельцу в истории.

## Технологии и их задачи

| Технология                    | Для чего используется                                                  |
| ----------------------------- | ---------------------------------------------------------------------- |
| **TypeScript**                | Общие типы и логика клиентской и серверной частей.                     |
| **React, React Router, Vite** | Веб-панель, страницы кампаний и сборка приложения.                     |
| **TanStack Query**            | Загрузка данных, обновление списков и состояния запросов в интерфейсе. |
| **React Hook Form и Zod**     | Формы кампаний и проверка введённых данных.                            |
| **Tailwind CSS и Base UI**    | Оформление и элементы интерфейса.                                      |
| **Hono и Cloudflare Workers** | HTTP API, приём событий Instagram и выполнение серверной логики.       |
| **Cloudflare D1 и Queues**    | Хранение кампаний и истории; обработка входящих событий в фоне.        |
| **Instagram API и OAuth**     | Подключение аккаунта, комментарии, сообщения и проверка подписки.      |
| **Vitest**                    | Автоматические проверки логики, React-компонентов и Worker.            |

Версия в этой ветке рассчитана на одного владельца и один профессиональный Instagram-аккаунт. Материал передаётся HTTPS-ссылкой. Для работы с настоящим аккаунтом нужны настройки приложения Meta и разрешения Instagram API.

## Локальная разработка

Node.js 24, pnpm 11.15.1. Привязки Cloudflare описаны в [wrangler.jsonc](wrangler.jsonc), настройка окружения — в [техническом описании](docs/TECHNICAL_DESIGN.md). Секреты задаются локально и не добавляются в Git.

```sh
pnpm install
pnpm dev
```

```sh
pnpm check
pnpm build
```

`check` проверяет форматирование, линтер, границы модулей, типы и тесты. `build` собирает приложение.
